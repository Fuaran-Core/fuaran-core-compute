# Compute benchmarks — 2026-10-03, Intel Core i7-8650U, Phase 341 (Layer 6 re-measured natively, x64)

The x64 half of Phase 341. Phase 270's host-kernel verdicts were taken with the x64 build under
emulation on an Arm64 machine; the Arm64 half re-took them natively in
[`2026-10-03-snapdragon-x1e80100-phase-341.md`](2026-10-03-snapdragon-x1e80100-phase-341.md). This
file runs the same committed `Layer6` suites, with the same parameters, on a native x64 machine, so
the two files compare row for row. Every run here was taken with the machine quiet (see
"Sittings").

**The figure is the median.** Each suite ran as its own invocation:

```powershell
dotnet run -c Release --project benchmarks/Fuaran.Core.Compute.Benchmarks -- --filter '*Layer6.KernelPair*'
dotnet run -c Release --project benchmarks/Fuaran.Core.Compute.Benchmarks -- --filter '*Layer6.Comparisons*'
dotnet run -c Release --project benchmarks/Fuaran.Core.Compute.Benchmarks -- --filter '*Layer6.Morsels*'
dotnet run -c Release --project benchmarks/Fuaran.Core.Compute.Benchmarks -- --filter '*Layer6.ParallelGroupBy*'
```

The union is the Arm64 file's `--filter '*Layer6*'`. The morsel sweep rebuilt the harness with
`Kernels.MorselRows` set to 4,096, 16,384 and 32,768 and ran `*Layer6.Morsels*` at each. Those edits
were never committed, and the constant is 8,192 at this commit. Every suite's `GlobalSetup` asserts
its answers before anything is timed, as in the Arm64 file.

process on the machine. Before and after each invocation the CPU load was sampled

`fsc` and `node` process that was not part of this run; the same was sampled every 30 seconds while
it ran.

Discarded: an earlier x64 sitting the same afternoon, on a different, uncommitted harness, taken

run. Neither contributes a figure here.

The portable rows agree within about 7% across builds and sittings. The exception is `compiled` at

to 1.37 ms), so it belongs to the morsel layout, not to noise.

### Reading

- **10,000 rows.** 4,096 leads, as on Arm64: three morsels against two.
- **100,000 rows.** The compiled `Filter` is tied across sizes. The `Derive` is 21% to 27% faster at
  32,768 than at 8,192, in both sittings, a gap of about two standard deviations each time. At
  32,768 the input splits into four morsels, one per physical core of this machine; at 8,192 it is
  thirteen. On the 12-core Arm64 machine 8,192 was best or tied here. The best morsel size at this
  row count follows the core count, which a fixed constant cannot.
- **1,000,000 rows.** The compiled `Filter` favours 8,192 by about 10% in both sittings. The `Derive`
  read 32,768 ahead by 20% in the first sitting and tied in the second, so it is unsettled, as it is
  on Arm64 (where the quiet sitting favoured 16,384).
