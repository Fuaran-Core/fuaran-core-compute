# Compute benchmarks — 2026-10-03, Intel Core i7-8650U, Phase 355 (the incremental state's wire form)

Phase 355 gives `IncrementalEval` a canonical wire form (`IncrementalCodec`), so a consumer that runs
in fresh processes can store the state after a run and resume from it in the next. This file records
what the encoded state weighs against the source it was built over, and what encoding, decoding and
resuming cost beside a full evaluation, for the corpus's three Scaling pipelines at 1,000, 100,000
and 1,000,000 rows.

## Verdict

| Question | Answer |
|---|---|
| A refresh from a decoded state against a refresh from the original | **Equal, in table and in footprint**, on both hosts: `IncrementalDelta.stateLaws` green over 3 seeds of 60 draws on .NET and under node before anything was measured, and asserted again for every row of the tables below (the state decoded from a carrying encoding, and from a detached one over its source) |
| The encoding across hosts | **Byte-identical in length** at every size both hosts measured: the same character counts on .NET and under node |
| Size, carrying its source | **1.11 to 1.29 times** the source's own column wire (`ColumnCodec.encode`) |
| Size, detached | **0.62 to 0.74 times** the source's column wire |
| Encode at 1,000,000 rows, .NET | **7.0 to 8.4 s** |
| Decode at 1,000,000 rows, .NET | **11.8 to 12.6 s** carrying its source; **6.4 to 7.3 s** detached, over a supplied source |
| A full evaluation at 1,000,000 rows, .NET | **0.09 to 0.38 s** |
| Does resuming from an encoded state beat a full evaluation on these shapes | **No, at any size, on either host.** Decoding alone costs 33 to 128 times the full evaluation at 1,000,000 rows on .NET (17 to 78 times detached), and 19 to 231 times at 100,000 rows under node |
| node at 1,000,000 rows | Not measured: assembling the encoding exhausts node's default heap, which ends the process |

## What the figures say

The state is linear in the source. For each source row it holds an identity token, one cached cell per
evaluating step the row reached, and (under a maintained `GroupBy`) the row's group index and its
place in the group's member list; beside those, the source and the result. The Scaling pipelines
evaluate one comparison per row, so the state they cache is about as large as the table and what it
saves per row is one comparison.

Reading it back is a JSON parse of 28 to 57 million characters at 1,000,000 rows, about 12
microseconds per source row on .NET (7 detached). A full evaluation of these pipelines costs 0.1 to
0.4 microseconds per row. The wire form therefore pays only where an evaluation costs more per row
than the read does: an expensive expression, a relation resolved from elsewhere, or a source that is
itself costly to obtain in full. No pipeline in this corpus is one of those, and the corpus was not
widened to find one: the phase asked for the corpus's shapes.

Two things were done to the format on the way to these figures, both measured against the first
draft at 1,000,000 rows on .NET, over the two pipelines its run completed (encode 14.9 and 19.9 s,
decode 11.6 and 32.9 s, a carrying encoding at 1.29 and 1.34 times the source):

- **The digest is over the stored bytes.** The document is a fixed frame around its body's canonical
  text, so decode hashes the body's substring and parses it once; the first draft parsed the
  document, rendered the body again and hashed the rendering.
- **The source is rendered once**, its text serving as the fingerprint's pre-image and as the member;
  and a group's members are written as indexes into the row tokens the state already carries, where
  the first draft wrote each token a second time (12 to 14 per cent of a group-bearing encoding).

What remains is the cost of the JSON read and write through the substrate's `JVal` model, which this
phase does not change.

## The incremental state's wire form — .NET

`Source` is the source's column wire (`ColumnCodec.encode`); `State` is `IncrementalCodec.encode` and
`Detached` is `encodeDetached`, each in characters (the corpus is ASCII, so characters are UTF-8
bytes) and as a multiple of the source. `Decode over source` is `decodeOver`, which fingerprints the
supplied table. `Diff + refresh` is what a second process does after decoding: `Delta.diff` against
the decoded state's source, then `refreshOn` over the one-row edit. `Full evaluation` is
`DataFrame.evalPipeline` over the edited table.

Under node an encode costs 12 to 17 times what it costs on .NET at 100,000 rows and a decode 6 to 10
times. Where that time goes inside the encode (the digest's `uint32` arithmetic, the string assembly,
the `JVal` construction) was not separated.

## Instrument

.NET 10 (SDK 10.0.401), Release; node v22.20.0, the sources compiled by Fable 5.0.0. One program on
both hosts: the node harness's `state` family
(`benchmarks/Fuaran.Core.Compute.Benchmarks/Node/Program.fs`),

```
dotnet run -c Release --project benchmarks/Fuaran.Core.Compute.Benchmarks/Node -- 3 state
pwsh benchmarks/Fuaran.Core.Compute.Benchmarks/Node/run-node.ps1 -FableFrom <dir> -Runs 3 -Only state
```

Each figure is the best of three single calls, wall clock, with a millisecond clock under node. A
single call rather than a calibrated batch: at these sizes one call is the unit a job pays. The
machine was otherwise idle but is a laptop; read the figures to their first digit. Before any row is
timed the program runs `IncrementalDelta.stateLaws` over three seeds on its own host, and for each
row it asserts that the refresh from the decoded state, and from the state decoded over its source,
equals the refresh from the original in table and in footprint.
